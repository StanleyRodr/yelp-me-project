# 012 — Plan: Notificaciones push (FCM)

> Fecha: 2026-11-26 · Rama: `feature/fcm` (desde `main`, tras fusionar el plan 011)
> Referencia: `docs/plans/principal-plan.md` (secciones 2.3, 9, 13.8)

## Objetivo

Avisar con notificación push: a los **contactos vinculados** cuando un usuario crea una solicitud, y al **solicitante** cuando el admin cambia el estado. El sistema sigue funcionando completo sin FCM (si falla, solo se registra en el log).

## Punto de partida
- `usuarios.fcm_token` (un dispositivo por usuario). Login y registro ya aceptan `fcm_token`; logout lo borra (plan 003).
- Solicitudes y cambios de estado en `SolicitudController`, `EstadoSolicitudController` y `Admin/EstadoSolicitudController` (plan 005).
- App con sesión, detalle de solicitud y llamadas (planes 008–011).

## Decisiones
- **Proyecto Firebase** creado por la persona dueña del repo (consola de Firebase). Cuenta de servicio JSON **fuera de git**: local en `backend/storage/app/firebase/credenciales.json` (ignorado); producción en variable `FIREBASE_CREDENTIALS_BASE64` (plan 013).
- Backend con `kreait/laravel-firebase` (API v1). Interfaz `App\Support\Notificador` con dos implementaciones: `NotificadorFcm` y `NotificadorNulo` (sin credenciales o en pruebas). Pruebas con un `NotificadorFalso` que guarda lo enviado.
- Envío **después del commit** (`DB::afterCommit`); errores se registran y no cambian la respuesta. Token inválido (`NotFound`/`InvalidMessage`) → `fcm_token = null`.
- **Nuevo endpoint** `PUT /api/sesion/fcm` `{ fcm_token }` (rol usuario) para cuando Firebase rota el token.
- Mensajes:
  | Evento | Destino | Título / cuerpo | Datos |
  |---|---|---|---|
  | Usuario crea solicitud | Contactos vinculados activos del creador | "Carlos pidió ayuda" / título de la solicitud | `tipo=alerta_contacto`, nombre, teléfono, título, latitud, longitud, ubicacion_nombre |
  | Admin → Enviado | Solicitante | "Tu ayuda va en camino" | `tipo=estado`, `solicitud_id`, `estado` |
  | Admin → Rechazado | Solicitante | "Tu solicitud fue rechazada" / motivo | ídem |
  | Admin → Terminado | Solicitante | "Tu solicitud se marcó como terminada" | ídem |
- El contacto que recibe la alerta **no** consulta la solicitud en la API (es de otro usuario): la app muestra los datos del mensaje en `AlertaContactoActivity` (mapa + "Llamar").
- Android: canales "Alertas de contactos" (importancia alta) y "Estado de mis solicitudes". Permiso `POST_NOTIFICATIONS` tras el login.
- `google-services.json` **fuera de git** (`mobile/app/google-services.json` en `.gitignore`); cómo obtenerlo queda en el README de mobile.
